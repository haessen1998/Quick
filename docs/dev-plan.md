## 建议验收路径

1. `wails3 task dev` 启动 Quick Dev。首次使用开发配置为空是预期行为，正式配置没有被删除。
2. 在字符串格式化输入 `{"id":9223372036854775807}`，执行并切换压缩模式；确认数字未变、输入保留。
3. 新建第二个文档，输入不同内容；来回切文档、切首页再返回，确认数据独立。关闭文档后点击通知中的撤销。
4. 用 Ctrl/⌘K 搜索 Base64 或 regex，直接进入对应工具。默认 1000×618 窗口打开小Q，确认编辑区域没有被挤成细列。
5. 在 JSON 中制造语法错误，点击错误定位。切换英文，确认文档中的中文字段没有被翻译。
6. 用开发专用 AI 配置要求小Q“将这段 Base64 解码，格式化为 JSON，再用 JSONPath 提取字段”。观察每一步和执行记录；无需事先打开相关页面。
7. 请求发送 HTTP、调用第三方 MCP 等操作，核对逐次授权和取消行为。真实文件/进程操作应先用专用测试文件与测试进程验收。

## 配置和发布变化

- Go 开发配置：原 Quick 配置目录下的 `dev/`；正式配置继续使用原位置。导航图标也分离。应用标题分别为 Quick Dev / Quick。
- 浏览器存储：开发模式使用 `quick-dev:` 命名空间，正式模式沿用原键，避免开发版读入或清除正式版遗留凭据缓存。模式判断使用 Vite `MODE`，兼容 `build:dev`。
- 敏感配置：AES-GCM 的随机密钥存入系统凭据存储，文件内保存密文。旧固定密钥密文只用于迁移；取得系统密钥并验证写入后才替换文件。系统密钥丢失时拒绝覆盖现有密文，普通偏好仍可读取。不要仅复制新版 settings.json 作为跨设备凭据备份。
- A/B 测试：`wails3 build DEV=true QUICK_DEBUG_MCP=true` 显式构建调试版，再手动启用 Quick App MCP。正式构建同时使用 `production,mcp` 会编译失败。普通第三方 MCP 客户端仍是正式功能。
- `frontend/tests/` 是独立测试源，不被应用入口导入；测试 harness 仅供 Vite 开发服务访问。生产 `dist` 检查排除测试标记。CLI 快照、截图和日志在忽略目录中；没有向产品添加测试 Provider、测试凭据或自动测试入口。
- 更新了已有发布工作流的测试命令，使其检查正式配置和测试入口隔离；没有新增 GitHub PR 门禁。
- 新增运行依赖：lossless-json、html-minifier-terser、Go go-keyring；测试依赖 tsx、Playwright CLI。兼容更新了 fast-uri、qs 的锁定版本，最终 npm audit 无已知告警。

## 已知限制与验收边界

- 浏览器模式没有 Wails 原生桥，配置与原生服务预览会出现 bridge/404 日志；这些测试验证前端与本地工具执行，不代表真实 AI Provider、远程 MCP 或原生文件对话框已经端到端验收。
- 尚未进行 macOS/Linux 原生运行、系统钥匙串实际交互、安装包签名与商店发布测试。凭据单元测试使用 mock，不改动系统真实凭据。
- 工作流取消能终止后续步骤、授权等待和前端正则 Worker；已经进入不支持取消的 Go 操作可能完成，不能把停止生成当作事务回滚。MCP STDIO 取消会关闭对应会话。
- 当前工作流是顺序执行，不含并行分支、条件分支、崩溃后恢复或跨步骤事务回滚。
- 工作文档和聊天只提供会话内恢复。草稿磁盘保存、跨设备同步、Token/费用统计及完整会话管理不属于本轮新增界面。
- 生产构建仍提示部分大 chunk（主要为 Mermaid、AI/Markdown 相关依赖）。页面 DOM 已按需挂载，但部分模型/算法依赖仍会初始化；本轮没有声称完成启动性能优化。
- 只保留近期执行记录，超过记录预算后旧结果 ID 会过期；AI 需要重新执行来源工具，不能把截断摘要当作完整结果。
